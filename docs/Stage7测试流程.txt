前置条件
--------

  - 存款连续加成：+0.5%/天（默认 0.005 = 0.5%）

  - 贷款连续加成：+1.0%/天（默认 0.01 = 1.0%）

测试二：停售衰减利率（7.2）
═══════════════════════════════════════════════════════════════════

目标：停止出货后，利率每天衰减。

Config 参考值：
  - 存款衰减：-0.5%/天（默认 0.005 = 0.5%）
  - 贷款衰减：-1.0%/天（默认 0.01 = 1.0%）
//记下利率: 存款 __20.330_%   贷款 _25.330__%
步骤：
  1. 接续测试一（已有连续售卖天数后），停止出货土豆
     什么都不卖，直接睡觉

  2. 起床后打开手机→土豆公司，查看利率
     预期: 存款利率 -0.5%, 贷款利率 -1.0%（不再有连续加成，开始衰减）

  3. 连续 5 天不出货土豆，每天记录利率
     注意: 手机每打开一次都会刷新利率显示
//记下利率: 存款 __14.830_%   贷款 _14.330__% 贷款利率低于存款利率，存在问题
//记下利率: 存款 __14.830_%   贷款 _14.330__% 第二天无变化，存在问题，同时发现21%依旧为繁荣模式，不合理
//记下利率: 存款 __14.830_%   贷款 _14.330__% 第三天无变化，存在问题，9%燃料进入稳定模式，不合理。
//记下利率: 存款 __14.830_%   贷款 _14.330__% 第三天无变化，存在问题，0%燃料进入饥饿模式，不合理
//总结，不出售衰减设置失败，且模式对应的燃料占比错误，燃料耗尽进入饥饿模式而没消失，日消耗燃料确实有配合模式变化。模式不符合value3.txt的3.1要求。
  观察数据点:
    停售第1天 → 存款基础-0.5%, 贷款基础-1.0%
    停售第2天 → 存款基础-1.0%, 贷款基础-2.0%
    停售第3天 → 存款基础-1.5%, 贷款基础-3.0%
    ...
    衰减直到触及 DepositRateFloor（默认 -2%）或进入负数

验证:
  - 连续售卖天数归零（ConsecutiveSellDays = 0）
  - 利率每天 -0.5%（存款）/ -1.0%（贷款）
  - 若配置允许负利率(AllowNegativeInterest=true)，衰减可低于0%
  - 若不允许负利率(AllowNegativeInterest=false)，利率在0%处钳位

测试四：打压叠层与衰减（7.3 续）
═══════════════════════════════════════════════════════════════════

目标：验证多次售卖叠层和逐天衰减。

步骤：
  1. 接续测试三，连续 3 天去皮埃尔卖土豆（每天卖 20+ 个）
     player_add (O)192 30 → 去皮埃尔商店卖 → 回家睡觉

  第1天（测试三已做）: stacks=2, days=5
  第2天: 卖30个→ stacks=min(2+2, 3)=3, days=5
  第3天: 卖30个→ stacks=min(3+2, 3)=3, days=5（已达上限）

  2. 停止卖土豆，每日查看存档中的 CropSuppressions 数据
     每天睡觉后 RemainingDays 减 1

  3. 当 RemainingDays=1 → 睡觉后 → RemainingDays=0 → Stacks 减 1
     若 Stacks>0 → 重置 RemainingDays=5
     若 Stacks=0 → 条目从 CropSuppressions 中移除

  观察数据点:
    关闭商店当天 → stacks=2, days=5
    第1天起床后 → stacks=2, days=4
    ...
    第5天起床后 → stacks=2, days=0 → 减层 → stacks=1, days=5
    第10天起床后 → stacks=1, days=0 → 减层 → stacks=0 → 删除条目

    利率变化:
    第1-5天: 扣 2×2%=4%
    第6-10天: 扣 1×2%=2%
    第11天起: 无打压（条目删除）

验证:
  - 打压叠层最大 3 层（不会超过）
  - RemainingDays 归零时正确减层
  - 最后一层到期后 Cropsuppressions 条目删除
  - 利率在打压结束后恢复正常（仅受连续/衰减影响）

测试五：计算顺序验证（7.4）
═══════════════════════════════════════════════════════════════════

目标：验证多因素叠加时计算顺序正确。

公式: 基础利率 → +连续/衰减 → -压制 → ×运气 → +天气 → 钳位

步骤（同时有连续售卖 + 打压）：
  1. 先连续出货土豆 5 天（建立 +2.5% 存款加成）
  2. 同时去皮埃尔卖土豆（施加 2 层打压 = -4%）
  3. 打开手机查看利率

  预期计算（假设土豆 R=15.33%, 无天气/满运气=0）：
    基础存款 = R = 15.33%  (0%<R≤20%, 不打折)
    + 连续加成 = +2.5%
    - 打压 = -4.0%
    = 13.83%
    × 运气(假设 DailyLuck=0, LuckCoeff=2.5) = ×1.0
    + 天气(SunBonus=0) = 0
    最终 = 13.83%

  测试下雨天（IsRaining=true, RainBonus 可能非零）：
    预期: 在 × 运气后 + RainBonus

验证:
  - 数值在合理范围（+连续&-打压后×运气+天气）
  - 雨天比晴天利率多/少 RainBonus 的值
  - 负利率在 AllowNegativeInterest=false 时被钳位到 0%

2024-05-04 修复记录
═══════════════════════════════════════════════════════════════════

修复 1: 衰减改为累计（DecayDays）
  - 之前: 停售后每天固定 -0.5%/-1.0%，不累计
  - 现在: 停售第1天 -0.5%, 第2天 -1.0%, 第3天 -1.5%，直到触及上限
  - DecayDays 有售卖时归零；无售卖且 HasSoldHistory 时叠加
  - 衰减上限与连续加成上限相同（存款±5%, 贷款±10%）

修复 2: BankMenu 动态公司使用正确策略
  - 之前: 所有公司（含动态）都用 FixedCompanyInterestStrategy 显示
  - 现在: 动态公司用 DynamicCompanyInterestStrategy，固定公司用 Fixed
  - 这修复了手机上动态公司贷款基础利率显示为 R（而非 R×1.5）的问题

修复 3: 3-tier 税率规则统一在 GetAllCompanyDefinitions 应用
  - 之前: DynamicCompanyInterestStrategy 内部重复计算 3-tier
  - 现在: CompanyDefinition 的基利率已含 3-tier 规则，策略直接使用
  - 这使"基础利率"显示正确: 土豆贷款基础 = 15.33%×1.5 = 23%

已知待处理:
  - 测试三: Joja 杂货店游戏内不收农作物（只有皮埃尔收），正常游戏现象
  - 取款不减少累计利息（AccumulatedInterest），玩家不确定取走的是本金还是利息
  - 利息累计可超过存款上限，但无法存入（提示超限），可正常取出
  - 公司状态（繁荣/稳定/饥饿/濒死）阈值需对照 value3.txt 确认
