## 阶段四：基础利率与计息

### 步骤 4.1：实现固定每日利率
- 每家公司的存款利率从 config 读取（日利率）
- 每日早晨自动结算：
  - 利息 = 存款余额 × 日利率
  - 利息加入存款余额
- 测试：睡觉触发计息，确认存款余额增加

### 步骤 4.2：接入每日运气值
- 获取游戏当天的运气值
- 运气值映射为利率浮动：
  - 如运气 +0.05 → 日利率额外加 X%（可配置）
- 结算时使用调整后的利率
- 测试：好运/坏运天气下，确认利息增减差异

### 步骤 4.3：接入天气影响
- 获取当天天气类型
- 为不同公司配置天气加成（config）
- 结算时叠加天气加成
- 测试：雨天/晴天切换，对比利息变化

### 步骤 4.4：复利/单利开关
- config 中增加选项：单利 / 复利
- 单利：利息只按本金算
- 复利：每日利息加入本金，次日继续生息
- 测试：两种模式分别验证利息计算

### 步骤 4.5：负利率配置
- config 中增加：允许负利率（是/否）
- 如果允许，利率可跌破 0%，存款缩水
- 如果不允许，最低利率钳位在 0%
- 测试：用坏运+负利率公式，确认是否触底

## 阶段五：贷款基础功能

### 步骤 5.1：贷款数据模型
- 在固定公司数据结构中增加：
  - 贷款本金
  - 贷款日利率（独立于存款利率，从 config 读取）
  - 累计未还利息
  - 贷款上限（从 config 读取）
  - 还款周期（7 天 / 14 天，玩家借款时选定）
  - 下次还款日（游戏日期）
- 测试：创建测试数据，确认所有字段正确读写

### 步骤 5.2：借款按钮与逻辑
- UI 添加"借款"按钮
- 点击后弹出：
  - 还款周期选择（7 天 / 14 天）
  - 借款金额输入
- 借款检查：
  - 当前贷款余额 + 新借款 ≤ 贷款上限
  - 玩家身上现金增加，贷款本金增加
  - 记录还款周期和到期日
- 测试：正常借款、超额借款、已有贷款时再借

### 步骤 5.3：还款按钮与逻辑
- UI 添加"还款"按钮
- 显示当前应还信息：
  - 本金、累计利息、到期日
- 玩家输入还款金额
- 还款顺序：优先偿还逾期利息 → 正常利息 → 本金
- 可提前全额或部分还款
- 测试：正常还款、部分还款、超额还款、没钱还款

### 步骤 5.4：到期自动扣款
- 每日开始时检查所有固定公司贷款
- 若当天为到期日：
  - 计算应还总额 = 本金 × 利率 × 周期天数 + 本金（或可选还本部分）
  - 从玩家现金自动扣除
  - 扣除成功 → 贷款清零，标记已结清
  - 扣除失败 → 进入本金欠债状态
- 测试：到期有钱、到期没钱两种情况

### 步骤 5.5：贷款每日计息
- 每日早晨结算所有固定公司贷款利息
- 利息 = 当前贷款本金 × 贷款日利率
- 利息累加到"累计未还利息"
- 利率同样受运气、天气影响（复用阶段四逻辑）
- 14 天还款周期享有利率折扣（config 控制，如 -0.5%）
- 测试：确认每日利息正确累加，到期日总额正确

## 阶段六：动态公司——诞生与基础运营

### 步骤 6.1：监控玩家出货行为
- 监听玩家通过出货箱卖东西的事件
- 记录每种商品的累计出售数量（按基础物品ID，不考虑品质）
- 数据按玩家存储到存档
- 测试：卖东西后睡觉，检查存档中计数是否正确

### 步骤 6.2：连续售卖天数追踪
- 为每种商品记录：
  - 最近一次通过出货箱售卖的日期
  - 连续售卖天数
- 每日开始时自动更新：
  - 昨天卖出 → 连续天数 +1
  - 昨天未卖出 → 连续天数重置为 0
- 数据存储到存档
- 测试：连续卖 3 天/断 1 天/再卖，确认计数逻辑正确

### 步骤 6.3：触发新公司生成
- 每日开始时检查所有商品
- 当某商品累计出售数量 ≥ config 阈值（默认 50）时
- 检查是否已存在对应动态公司
- 若不存在，生成新动态公司：
  - 名称：商品名 + "公司"（如"土豆公司"）
  - 基础存款日利率 = 该作物日回报率 × 存款系数（从 config 读取）
  - 基础贷款日利率 = min(日回报率 × 贷款系数, 硬上限)
  - 初始存款上限（从 config 读取，默认 500,000g）
  - 贷款上限根据作物价格等级（低/中/高，从 config 读取）
  - 公司状态标记为"正常运营"
  - 记录生成日期
- UI 公司列表自动刷新
- 测试：通过控制台/正常游玩触发某作物达标，确认公司生成

### 步骤 6.4：动态公司存款与取款
- 复用阶段三的存款/取款逻辑
- 动态公司的存款界面与固定公司一致
- 存款上限从公司数据读取（初始值来自 config）
- 测试：在动态公司存钱/取钱，确认数据独立

### 步骤 6.5：燃料系统接口定义【V3.3 新增】
- 新增 IFuelService 追加方法：RecordShippingBinSale, RecordExternalPurchase, RecordExternalSale, GetDisplayFuelStock
- 新增 FuelConstants 静态类（FuelPointsPerCrop = 10 等常量）
- 测试：编译通过，接口可被引用

### 步骤 6.6：燃料系统基础实现【V3.3 新增】
- 实现 IFuelService 新增方法
- 内部所有库存使用 int（燃料点 FP），UI 展示层除以 10
- 实现：
  - RecordShippingBinSale：stock += quantity × 10（铱星额外 +10，金星额外 +5）
  - RecordExternalPurchase：stock -= quantity × 5
  - RecordExternalSale：stock -= quantity × 5
- 阈值公式中的 Y 也转换为 FP（Y × 10）
- 测试：单元测试验证买卖不对称性（买1个 -5FP，出货1个 +10FP）

### 步骤 6.7：公司生成时注入初始燃料库存【V3.3 新增】
- 新公司生成时调用 IFuelService.AddFuelStock(companyId, initialFuelPoints)
- initialFuelPoints = Smax × 0.3（内部单位 FP）
- 测试：新公司生成后，手机 UI 显示库存 > 0

### 步骤 6.8：资产池基础实现【V3.3.1 新增】
- 新增 AssetPoolService
- 有效贷款上限 = 原始贷款上限 × 状态乘数
- 资产池 = 有效贷款上限 − 已贷出未归还本金
- 取款限制：maxWithdraw = min(玩家存款, max(0, 资产池))
- 测试：饥饿期/濒死期取款受限验证

## 阶段七：动态公司利率波动（核心驱动）

### 步骤 7.1：连续售卖加成利率
- 每日早晨结算利率时，读取该商品的连续售卖天数
- 连续售卖天数越多 → 对应公司存款利率、贷款利率都上涨
- 加成公式：每连续一天 +X%（存款）/+Y%（贷款），从 config 读取
- 加成有上限（从 config 读取）
- 测试：连续卖 5 天，确认利率逐日上升，触发上限后不再增加

### 步骤 7.2：停售衰减利率
- 若当天未通过出货箱卖出该商品
- 利率每天按固定比例/数值衰减（从 config 读取）
- 衰减至基础利率以下继续衰减，直到触及负利率下限（若允许）
- 测试：停止售卖后睡觉，确认利率逐日下降

### 步骤 7.3：竞争对手售卖打压
- 监听玩家在皮埃尔/Joja 商店直接出售商品的事件（非出货箱）
- 若售出的商品有对应动态公司：
  - 该公司存款利率立即下降（下降幅度按出售数量阶梯计算，config 控制）
  - 该公司贷款利率同步下降（比例 config 控制）
  - 打压效果持续 N 天（config 控制）
  - 打压效果可叠加，有最大叠层数（config 控制）
- 同时皮埃尔/Joja 存款利率微升（可配置幅度）
- 测试：去皮埃尔卖 20 个土豆，确认土豆公司利率下降，持续天数正确

### 步骤 7.4：每日利率汇总计算
- 每日早晨按以下顺序计算每家公司的最终利率：
  1. 从基础利率出发
  2. + 连续售卖加成（或停售衰减）
  3. - 竞争打压效果（按剩余持续天数）
  4. × 运气倍率（阶段四逻辑）
  5. + 天气加成（阶段四逻辑）
  6. 钳位到允许范围（是否允许负利率、上下限）
- 测试：多种因素叠加，确认计算顺序和结果正确

## 阶段八：利息欠债、本金欠债与破产保护

> **状态：✅ 已完成（2026-05-14）**
> 实际实现与原始设计有重大偏差，以下逐步骤标注实际行为。

### 步骤 8.1：动态公司每日扣息 ✅
- 每日早晨对玩家的所有动态公司贷款执行扣息
- 利息 = 贷款本金 × 贷款日利率（使用阶段七算出的实际利率）
- 从玩家现金扣除：
  - 现金足够 → 正常扣除，利息清空
  - 现金不足 → 扣到 0，剩余利息转入"逾期利息"，进入**利息欠债**状态
- **实际：已实现，LoanService.DailyTick 中 isDynamic 分支处理**

### 步骤 8.2：利息欠债状态（单利/复利） ✅
- 利息欠债时，按 config 选择的计息方式处理：
  - 单利模式（推荐）：逾期利息单独记录，不滚入本金
  - 复利模式：逾期利息加入本金（利滚利）
- 利息欠债状态下，玩家仍可借款、取款
- **实际：已实现，OverdueInterest 字段独立追踪，UseCompoundInterest 控制复利**

### 步骤 8.3：本金欠债状态（到期无法还款） ✅
- 固定公司贷款到期自动扣款失败时，进入**本金欠债**状态
- 宽限期：N 天（config 控制，默认 1 天）
- 宽限期内：
  - 利息继续计算（按罚息利率）
  - ~~该玩家所有借款功能立即暂停~~ **【实际修正：逾期不禁止借款，只有破产禁借款】**
- 宽限期结束仍未还款 → 强制从存款划扣：
  - 扣款顺序：低利率账户优先
  - 优先偿还逾期利息 → 正常利息 → 本金
- **实际：到期现金不够→进入宽限期→宽限期结束→存款全扣仍不够→触发破产冻结**
- **⚠ 逾期部分还款不再重置到期日（修复了"还1g就续期"的漏洞）**

### 步骤 8.4：破产状态判定与执行 ✅ 【大幅修正】
- ~~每日扣息/还款后检查~~ → **【修正：只在强制划扣失败时触发】**
- 触发条件：宽限期结束→强制划扣(现金+全部存款)→仍不够还→该笔贷款冻结
- 破产状态规则（最终实际行为）：
  - **【修正】存款利息照常计算（不冻结）**
  - **【修正】禁止借款（不禁止取款/存款）**
  - 每日出货收入 + 日间所有非取款收入的 50% 强制扣除用于还债
  - 冻结贷款：停息（0%）、无限期、不扣罚息
