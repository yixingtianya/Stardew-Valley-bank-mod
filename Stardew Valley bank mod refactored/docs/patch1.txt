勘误六：联机财产分配与存款分割机制

问题来源：
原版星露谷在刘易斯家中的“财产分配”功能，会将联机存档中的共同现金按玩家数量分割为个人独立现金。如果我们的银行存款不跟随分割，就会出现两个问题：

1. 不分家时，存款按 ID 独立会让合作阶段的金融信息不透明，玩家无法共享账户信息进行协作。
2. 分家后，如果银行存款继续保持“共同状态”，会导致资金归属混乱。

修正方案：

1. 不分家时的存款模式：共同账户

当 Game1.player.team.useSeparateWallets == false（未分家）时：

· 所有玩家的银行存款是共同账户，大家看到同一个余额、同一套存款/贷款数据。
· 任何玩家的存入/取款操作都直接影响共同账户。
· UI 上不区分“谁的存款”，只显示“家庭存款”或“农场存款”。

2. 分家时：存款按人数均分

当玩家在刘易斯家完成财产分配时：

· 原版游戏会将共同现金均分给每个玩家。
· 我们的银行存款同步执行均分：将共同账户中的各项余额（存款本金、贷款本金、累计利息等）按在线玩家数量均分，写入各自的 modData 独立账户。
· 分家完成后，存款变为独立账户，每个玩家只能看到和操作自己的存款。

3. 分家后：存款独立账户

当 useSeparateWallets == true（已分家）时：

· 每个玩家的银行存款完全独立，按 playerId 隔离。
· UI 只显示本玩家的存款数据。

4. 代码实现要点

```csharp
// OnDayStarted 中检查分家状态变化
private void OnDayStarted(object sender, DayStartedEventArgs e)
{
    if (!Context.IsMainPlayer) return;

    bool wasSeparated = lastKnownSeparateWallets;
    bool isSeparated = Game1.player.team.useSeparateWallets;

    if (!wasSeparated && isSeparated)
    {
        // 刚完成分家，执行存款均分
        SplitBankAccountsAmongPlayers();
        // 广播新账户状态给所有客机
        BroadcastBankSnapshot();
    }

    lastKnownSeparateWallets = isSeparated;
    // ... 其余日结算逻辑
}

private void SplitBankAccountsAmongPlayers()
{
    int playerCount = Game1.getAllFarmers().Count(f => f.isActive());
    if (playerCount <= 1) return;

    // 对每个公司的共同存款执行均分
    foreach (var company in GetAllCompanies())
    {
        var commonAccount = GetCommonAccount(company.Id);
        int perPlayerDeposit = commonAccount.DepositBalance / playerCount;
        int perPlayerLoan = commonAccount.LoanPrincipal / playerCount;
        int perPlayerInterest = commonAccount.AccruedInterest / playerCount;

        int depositRemainder = commonAccount.DepositBalance % playerCount;
        int loanRemainder = commonAccount.LoanPrincipal % playerCount;
        int interestRemainder = commonAccount.AccruedInterest % playerCount;

        foreach (var farmer in Game1.getAllFarmers().Where(f => f.isActive()))
        {
            var personalAccount = GetOrCreatePersonalAccount(farmer.UniqueMultiplayerID, company.Id);
            personalAccount.DepositBalance = perPlayerDeposit;
            personalAccount.LoanPrincipal = perPlayerLoan;
            personalAccount.AccruedInterest = perPlayerInterest;
        }

        // 余数归主机（或静默舍弃，推荐归主机以保证总金额守恒）
        if (depositRemainder > 0 || loanRemainder > 0 || interestRemainder > 0)
        {
            var hostAccount = GetOrCreatePersonalAccount(Game1.MasterPlayer.UniqueMultiplayerID, company.Id);
            hostAccount.DepositBalance += depositRemainder;
            hostAccount.LoanPrincipal += loanRemainder;
            hostAccount.AccruedInterest += interestRemainder;
        }
    }
}
```

5. 新增约束

约束 说明
共同账户模式 useSeparateWallets == false 时，所有玩家共享同一套银行存款数据
分家均分 useSeparateWallets 从 false 变 true 的当天，执行存款等额均分
余数归主机 无法整除的余额归主机，保证总金额守恒（不凭空增减）
分家后独立 分家后，每个玩家的 modData 独立存储，UI 只展示本玩家数据
操作锁 分家当天（检测到状态变化时），所有金融操作按钮灰掉，直到日结算完成

6. 反作弊说明

· 分家前，任何玩家操作共同账户都是合法的（本来就是共同财产）。
· 分家执行的代码在主机端运行，客机无权干预均分逻辑。
· 分家结果通过 BankDataSync 广播给客机，客机 UI 同步更新为个人独立余额。



贷款必须与存款一起平分，理由如下：

---

逻辑推导

1. 财产分配的本质是“公平分割”：原版分家时，共同现金均分，意味着双方对共同财产享有平等权利。贷款作为共同债务，自然也应由双方平等承担。
2. 如果不平分贷款，会出现三种坏情况：
   方案 后果
   贷款全部归主机 客机无债一身轻，主机可能因贷款超存款而立即破产
   贷款全部归客机 客机可能直接破产，且主机可以“赖账”
   自由选择 玩家会选择对自己最有利的分配，导致系统被滥用
3. 平分的自洽性验证：
   · 假设共同存款 100,000g，共同贷款 60,000g，两人分。
   · 平分后：每人存款 50,000g，贷款 30,000g。
   · 净资产：每人 50,000 - 30,000 = 20,000g（总净资产 40,000g = 原来的 100,000 - 60,000）。
   · 借款上限：每人 20,000 × 200% = 40,000g，减去已有贷款 30,000g，剩余可借 10,000g。
   · 不存在负数或越界。
4. 如果贷款不跟随存款平分：
   · 玩家A分到存款 50,000g，贷款 0g，净资产 50,000g。
   · 玩家B分到存款 50,000g，贷款 60,000g，净资产 -10,000g → 借款上限 = 负数处理 → 直接破产风险。
   · 这不是公平分配，是陷阱。

---

修正规则

贷款跟随存款一起平分，没有自由选择模式。

在勘误六的 SplitBankAccountsAmongPlayers 方法中，贷款和累计利息与存款一并纳入均分逻辑（之前的代码示例已经包含贷款和利息的均分，这里再次确认）。

分家当天，贷款合同处理规则：

1. 共同贷款在分家时按人数等额拆分，余数归主机。
2. 拆分后的贷款，每人的还款周期、下次还款日保持不变（与原共同贷款一致）。
3. 拆分后，每人独立负责自己的那份贷款，互不影响。
4. 分家当天，所有贷款扣息和还款检测暂停一天（日结算已在分家前完成，分家后的次日才恢复）。

补充到勘误六的代码中

在 SplitBankAccountsAmongPlayers 方法中，贷款拆分的逻辑需要加上还款日同步：

```csharp
private void SplitBankAccountsAmongPlayers()
{
    int playerCount = Game1.getAllFarmers().Count(f => f.isActive());
    if (playerCount <= 1) return;

    foreach (var company in GetAllCompanies())
    {
        var commonAccount = GetCommonAccount(company.Id);

        // 保存原贷款合同信息
        var originalDueDay = commonAccount.LoanDueDay;
        var originalRepaymentPeriod = commonAccount.RepaymentPeriod;
        var originalDailyRate = commonAccount.LoanDailyRate;

        // 均分
        int perPlayerDeposit = commonAccount.DepositBalance / playerCount;
        int perPlayerLoan = commonAccount.LoanPrincipal / playerCount;
        int perPlayerInterest = commonAccount.AccruedInterest / playerCount;

        int depositRemainder = commonAccount.DepositBalance % playerCount;
        int loanRemainder = commonAccount.LoanPrincipal % playerCount;
        int interestRemainder = commonAccount.AccruedInterest % playerCount;

        foreach (var farmer in Game1.getAllFarmers().Where(f => f.isActive()))
        {
            var personalAccount = GetOrCreatePersonalAccount(farmer.UniqueMultiplayerID, company.Id);
            personalAccount.DepositBalance = perPlayerDeposit;
            personalAccount.LoanPrincipal = perPlayerLoan;
            personalAccount.AccruedInterest = perPlayerInterest;

            // 继承原贷款合同条款
            personalAccount.LoanDueDay = originalDueDay;
            personalAccount.RepaymentPeriod = originalRepaymentPeriod;
            personalAccount.LoanDailyRate = originalDailyRate;
        }

        // 余数归主机
        var hostAccount = GetOrCreatePersonalAccount(Game1.MasterPlayer.UniqueMultiplayerID, company.Id);
        hostAccount.DepositBalance += depositRemainder;
        hostAccount.LoanPrincipal += loanRemainder;
        hostAccount.AccruedInterest += interestRemainder;
    }
}
```
