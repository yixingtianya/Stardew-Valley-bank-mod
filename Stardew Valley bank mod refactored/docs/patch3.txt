补丁版本： V3.3.2
补丁类型： 机制新增 + 配置扩展
依赖： V3.3.1（公司状态操作限制重构）
影响范围： value2.docx §3、§5、§9 / 架构总3.0.txt §三 / 索引.docx §阶段九

一、核心规则

定义：

公司倒闭时，存款不总是清零。根据倒闭时公司所处的状态，按比例返还存款本金。

返还仅针对存款本金，不包括已计入的利息（利息在倒闭时归零）。

返还比例阶梯：

倒闭时状态 返还比例 设计逻辑
繁荣期 80% 产能过剩倒闭，玩家是超额供给的功臣，损失相对小
稳定期 50% 随机概率倒闭，玩家正常经营，损失适中
饥饿期 0% 供给不足致死，有充足预警且可取款割肉
濒死期 0% 7天窗口+入股救市均未能挽回，清零

返还示例：

· 某玩家在土豆公司有存款100,000g
· 公司稳定期倒闭 → 返还50,000g，损失50,000g
· 公司饥饿期倒闭 → 返还0g，损失100,000g
· 繁荣期倒闭（尽管概率较高）→ 返还80,000g，损失20,000g

与既有机制的协同：

· 资产池不影响返还——返还资金由系统生成，不消耗公司资产池
· 入股救市的翻倍存款也参与返还计算：翻倍后的存款本金 × 返还比例
· 濒死期7天窗口结束仍未脱离 → 强制清算倒闭，返还比例固定为0%
· 饥饿期取款受限：玩家可以在公司死亡前割肉（能取多少取决于资产池），取不出的部分公司倒闭时清零

二、配置规则

2.1 配置参数

参数 默认值 允许范围 说明
繁荣期倒闭返还比例 80% 0% ~ 100% 产能过剩死亡返还
稳定期倒闭返还比例 50% 0% ~ 100% 随机概率死亡返还
饥饿期倒闭返还比例 0% 固定0% 供给不足致死，不可调
濒死期倒闭返还比例 0% 固定0% 重组失败，不可调

2.2 阶梯校验（不可逆阶梯，强制生效）

核心原则：

繁荣期返还比例 ≥ 稳定期返还比例 ≥ 饥饿期返还比例（0%）

如果玩家（或配置文件）设置了违反阶梯的值，系统自动钳位至合法范围。（与固定公司贷款利率不能小于存款利率共用一个逻辑）

校验逻辑：

```
// 系统强制阶梯校验
稳定期返还比例 = min(稳定期返还比例, 繁荣期返还比例);
// 饥饿期和濒死期固定为0%，不接受任何配置
饥饿期返还比例 = 0%;
濒死期返还比例 = 0%;
```

违规示例与自动修正：

玩家设置 系统修正 说明
繁荣30% / 稳定60% 繁荣30% / 稳定30% 稳定期不能超过繁荣期
繁荣50% / 稳定50% 有效 邻接相同值允许
繁荣10% / 稳定5% 有效 递减排布合法
繁荣0% / 稳定0% 有效 全部归零，极端硬核模式
繁荣100% / 稳定100% 有效 繁荣和稳定都不损失，仅饥饿和濒死清零

2.3 允许归零

玩家（或服主）可以主动将所有返还比例设置为0%：

· 繁荣期返还比例 = 0%
· 稳定期返还比例 = 0%（系统自动钳位，不超过繁荣期）
· 结果：任何状态下倒闭，存款全部清零

这是为极端硬核模式保留的选项——公司不管怎么死，存款一律清零。不推荐普通玩家使用，但系统支持。

2.4 GMCM 配置界面

· 仅暴露“繁荣期倒闭返还比例”和“稳定期倒闭返还比例”两个滑块
· 饥饿期和濒死期不显示配置项（固定0%）
· 滑块说明文字：“稳定期返还比例不可超过繁荣期”
· GMCM 实时校验：拖动繁荣期滑块时，如果繁荣期值 < 稳定期当前值，自动将稳定期滑块拉低到繁荣期值

四、与其他补丁的关联

与 V3.3.1（入股救市）的关联：

· 入股救市的翻倍存款在倒闭时也参与返还计算
· 翻倍存款 × 返还比例（稳定期倒闭时：翻倍存款 × 30%）

与勘误六（联机财产分配）的关联：

· 分家后，各玩家独立账户的倒闭返还各自计算
· 返还金额不经过资产池，直接计入个人现金
